MXC for Ruby 0.1.0 is the first release: run untrusted commands from Ruby in an operating system sandbox that decides what they can read, write, and reach, and how long they get.

```sh
gem install mxc
```

Precompiled gems are available for Linux (x86_64 and ARM64, glibc and musl) and macOS (Intel and Apple Silicon), for Ruby 3.2 through 4.0.

## New

* **Run a command in a sandbox with one call.** `MXC.run("python3 build.py", readable: "app/skills", writable: "tmp/out", timeout: 30)` returns an `MXC::Result` with `stdout`, `stderr`, `exit_code`, `success?`, and `timed_out?`. By @crmne
* **Describe policies the Ruby way.** Chainable setters on `MXC.sandbox` (`with_readable`, `with_writable`, `with_denied`, `with_network`, `with_env`, `with_directory`, `with_timeout`, `with_backend`) and matching class macros on `MXC::Sandbox` subclasses. Paths take Strings or Pathnames, timeouts take anything with `to_f`, including `ActiveSupport::Duration`. By @crmne
* **No network by default, or only the hosts you list.** `with_network(allow: ["pypi.org", "*.pythonhosted.org"])` lets the command reach those hosts over HTTP and HTTPS and nothing else, and `Result#blocked` lists what was refused. By @crmne
* **Stream output and drive interactive processes.** Pass a block to `run` to receive `MXC::Chunk`s as they arrive, or `spawn` a process to `write`, `close_write`, iterate with `each`, `wait`, or `kill`. By @crmne
* **Know whether the machine can sandbox before you rely on it.** `MXC.supported?` starts a real sandbox once, `MXC.availability` explains a failure with a remediation, `MXC.backends` lists what MXC found, and `MXC.supports?(:network_policy)` answers capability questions. By @crmne
* **Run in Docker and Kamal.** A guide with a minimal seccomp profile, the trade-offs of each `/proc` setup, a Bubblewrap wrapper that stops sandboxed code from creating user namespaces, and a Kamal job role configuration. By @crmne

## Known limitations

* **Windows is not supported.** MXC's Windows backends do not build with the MinGW toolchain Ruby uses on Windows.
* **macOS is tested in CI only.** Bubblewrap on Linux is what the maintainer runs and tested by hand.
* **Host allow-lists only cover programs that honor `HTTP_PROXY` and `HTTPS_PROXY`.** Everything else, including raw sockets, UDP, and DNS, fails inside the sandbox. See [Policies](https://crmne.github.io/mxc/policies/#allowed-hosts) for what allow-lists do and do not protect against.
* **Network access on Linux needs extra packages:** `slirp4netns`, `iptables`, util-linux, and `/dev/net/tun`. Sandboxes without network access need only Bubblewrap.
* **Docker needs a relaxed seccomp profile.** [Running in Docker](https://crmne.github.io/mxc/running-in-docker/) explains exactly what it opens.
