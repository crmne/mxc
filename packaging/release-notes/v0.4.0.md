MXC for Ruby 0.4.0 runs programs built against Homebrew's libraries in macOS sandboxes, such as a Ruby that links GMP, libyaml, or OpenSSL.

```sh
gem install mxc
```

Precompiled gems are available for Linux (x86_64 and ARM64, glibc and musl), macOS (Intel and Apple Silicon), and Windows (x64 and ARM64), for Ruby 3.2 through 4.0.

## New

### Programs start with the libraries they link

```ruby
MXC.run(RbConfig.ruby, "-v", readable: RbConfig::CONFIG["prefix"])
# => ruby 3.3.8 (2025-04-09 revision b200bad6cd) [arm64-darwin25]
#    0.3.0 stopped it with dyld: Library not loaded: /opt/homebrew/opt/gmp/lib/libgmp.10.dylib
```

A Seatbelt sandbox reads the system's libraries, but not those a package manager installs. On macOS, the sandbox now reads the library files the command's program links, and those they link in turn, so a program built against Homebrew's libraries starts. Only those files become readable: not their directories, and never the whole Homebrew prefix. `with_libraries(false)`, the `libraries false` class macro, or `libraries: false` turns this off. By @crmne; thanks @stephankaag and @yorzi for the reports.

### Load the libraries of extensions

```ruby
extensions = Dir[File.join(RbConfig::CONFIG["archdir"], "**", "*.bundle")]

MXC.sandbox
  .with_readable(RbConfig::CONFIG["prefix"])
  .with_libraries_of(*extensions)
  .run(RbConfig.ruby, "-ryaml", "-e", "puts YAML.dump(ok: true)")
```

Programs also open libraries while they run, like the extensions Ruby and Python load on `require` and `import`. `with_libraries_of`, the `libraries_of` class macro, and the `libraries_of:` keyword name them, and the sandbox reads the libraries they link. By @crmne

## Known limitations

* **macOS only.** Linux and Windows sandboxes already read the system's libraries, so neither setting grants anything there. A program on Linux that links libraries outside the system, such as Homebrew's on Linux, still needs them in `readable`.
* **Needs the Command Line Tools.** MXC lists the libraries with `otool`. On a Mac without the Command Line Tools, nothing is granted, because `/usr/bin/otool` would offer to install them instead.
* **Libraries a program opens by name at run time,** without a file to inspect, still need `readable`.
