MXC for Ruby runs a command in an operating system sandbox and hands you back its output. You decide which paths the command can read and write, whether it gets the network, which hosts it may reach, and how long it may run.

```ruby
result = MXC.run("python3 build.py", readable: "app/skills", writable: "tmp/out", timeout: 30)
result.stdout
result.success?
```

Use it when your application runs code it did not write: scripts generated by a language model, skills uploaded by users, or build steps from a third party.

## How it works

The gem is an unofficial Ruby binding to [Microsoft's MXC](https://github.com/microsoft/mxc), an MIT-licensed sandbox library written in Rust. MXC drives the sandbox your operating system already has:

| Platform | Backend | Status in 0.3.0 |
| --- | --- | --- |
| Linux | [Bubblewrap](https://github.com/containers/bubblewrap) | Supported and tested, without process limits |
| Linux 6.2 and later | [Landlock](https://docs.kernel.org/userspace-api/landlock.html), where Bubblewrap cannot run | Supported and tested, without network access or process limits |
| macOS | Seatbelt (`sandbox-exec`) | Supported and tested, without memory or process limits |
| Windows | ProcessContainer (BaseContainer or AppContainer) | Supported and tested, without host allow-lists |

The gem compiles MXC into a native extension, so you install one gem and no separate service. Until MXC ships resource limits ([microsoft/mxc#1498](https://github.com/microsoft/mxc/issues/1498)) and a Landlock backend ([microsoft/mxc#1494](https://github.com/microsoft/mxc/issues/1494)), the extension builds [a fork of MXC](https://github.com/crmne/microsoft-mxc) that adds them. Precompiled gems cover Linux (glibc and musl, x86_64 and ARM64), macOS (Intel and Apple Silicon), and Windows (x64 and ARM64).
